  OVER() clause – defines a "window" (subset of rows) for the function to operate on.
🔹 PARTITION BY – splits the data into groups (like a GROUP BY, but windowed). it optional according to the requirement we can create batch like dept,Sex.
🔹 ORDER BY – orders rows within each partition.
🔹 ROWS BETWEEN ... – further refines the window by specifying range of rows relative to the current row.

1)UNBOUNDED PRECEDING to UNBOUNDED FOLLOWING
   ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
Meaning:
UNBOUNDED PRECEDING = the first row in the partition.
UNBOUNDED FOLLOWING = the last row in the partition.

select EMPNO , ENAME, JOB, MGR, HIREDATE, SAL,COMM,DEPTNO, \
         sum(SAL) over(partition by DEPTNO order by SAL rows between unbounded preceding and unbounded following) as Cumul_Sal \
          from emp_tbl

ORDER BY SAL:Sorts employees within each department by salary in ascending order.

ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING

Q2 :Top 2 Salaried Employees (Overall)— globally

SELECT *
FROM (
  SELECT *,
         RANK() OVER (ORDER BY SAL DESC) AS salary_rank
  FROM emp_tbl
) ranked
WHERE salary_rank <= 2;

 Explanation:
RANK() assigns the same rank if two employees have the same salary + also there is a problem with RANK() in ranking sequence no # 
(Skips ranks on ties?	✅ Yes (skips)) and Handles ties: Assigns same rank, next rank is skipped. and Ranking behavior:Like Olympic podium (1, 2, 2, 4)

ENAME	SALARY	salary_rank
Alice	5000	1
Bob	4000	2
Charlie	4000	2
David	3000	4


DENSE_RANK() Skips ranks on ties?: No skip (dense ranking) this is GOOD and Handles ties: Assigns same rank, next rank is sequential,and Ranking behavior: Like dense stack (1, 2, 2, 3).

This query returns all employees who rank in the top 2, including ties.

RANK() and DENSE_RANK() allow ties (e.g., two employees with the same salary both rank 1).
ROW_NUMBER() gives unique row numbers — no ties.

When to Use What?
Use RANK() if you're doing leaderboards where position gaps matter.
Use DENSE_RANK() when you just need unique rank values without gaps.
Use ROW_NUMBER() when ties should be broken arbitrarily
